# Wiki

## Производительность сервера

После изменения серверного кода, которое может повлиять на скорость обработки HTTP-запросов, запускайте:

```bash
bun run smoke:server
```

Команда последовательно выполняет 5 сценариев: создание аккаунта, создание поста, его редактирование, загрузку случайной картинки из `test/assets`, удаление поста, удаление картинки и удаление аккаунта. Каждый сценарий использует новый аккаунт и в `finally` повторяет удаление аккаунта, если шаг завершился ошибкой. По умолчанию выполняется 10 разминочных сценариев, которые не попадают в статистику, а затем 30 измерительных сценариев. Количество можно изменить через `SMOKE_WARMUP_RUNS` и `SMOKE_RUNS`.

Результат сохраняется в `docs/performance/server-smoke.json` в формате `дата → массив запусков`: каждый вызов команды добавляет новую запись с `runAt`, `warmupRuns` и `runs`. Для каждого шага фиксируются `avgMs`, `medianMs`, `p95Ms`, `p99Ms`, `minMs`, `maxMs`, `stdDevMs`, `avgReqPerSec`, `medianReqPerSec`, `successCount`, `errorCount` и commit (SHA и subject). Дополнительно сохраняются process CPU/RAM-снимки запуска в поле `system`. После успешного запуска в БД и MinIO не должно оставаться тестовых данных; единственный сохраняемый артефакт — статистика. Файл нужно коммитить вместе с изменением, чтобы видеть динамику.

Локальный интерактивный график в dev-режиме доступен как [http://localhost:5173/performance.html](http://localhost:5173/performance.html). В production его раздаёт статический хост Web-приложения. Страница получает историю через `/api/performance`, каждая точка соответствует отдельному запуску, и позволяет выбрать шаг, метрику и период (день, неделя, месяц или произвольный диапазон дат). Нажатие на точку показывает под графиком подробности именно этого запуска; выбор метрики влияет только на общую перспективу графика и карточек.

Smoke-тест требует запущенных PostgreSQL, Redis и MinIO, а также применённой схемы БД. К изменениям, требующим запуска smoke-тестов, относятся изменения в `apps/backend/src`, серверных API-контрактах, middleware, базе данных, Redis/MinIO-интеграциях и конфигурации сборки сервера. Изменения только в UI обычно не требуют этого запуска.

## Размер серверного бандла

Чтобы собрать минифицированный серверный entrypoint и вывести его размер, запускайте:

```bash
bun run build:server:size
```

Результат сборки создаётся во временной, игнорируемой директории `apps/backend/.server-build`.
